# Folmi 小精灵动作设计

Folmi 是有生命感的小写 **f**。沿用已选定 D3 的炭黑 `#222429` 与琥珀 `#E9AA47`，保留右上方的头、黑色椭圆眼、小折耳、横臂和左卷尾。性格是安静、有点好奇、做完事会给你一个回应。主要动作来自视线、耳朵、尾巴，身体始终保持 f 的辨识度。

[打开交互预览](folmi-motion.html)。页面可直接用 `file://` 打开，也可通过本地 HTTP 查看，无远程字体、脚本或网络请求。预览中的终端、命令和状态都是模拟内容，不会执行命令，也没有接入 App 业务。

## 源文件与分层

- [folmi-mascot.svg](../../Sources/Folmi/Resources/Brand/Mascot/folmi-mascot.svg) 是为动画制作的可编辑简化矢量重绘，**不是对生成图的自动精确描摹**。它使用更平的着色，让耳、眼、尾巴能单独变换。正式 App 图标仍以批准的 D3 图像为视觉依据。
- [motion.json](../../Sources/Folmi/Resources/Brand/Mascot/motion.json) 定义状态、时长、循环、优先级、进入退出条件与减少动态策略。
- SVG `viewBox` 固定为 `0 0 512 512`，背景透明。`data-part` 是稳定的动作节点接口，`id` 便于设计工具选择；多个实例内联时应移除或加前缀，避免重复 ID。
- `pose` 包裹身体动作；`body` 是主体，`ear` 是折耳，`eyes` 含左右眼，`eyelids` 是闭眼线条，`tail` 与主干有重叠，`accent` 是完成时的短暂光线。仅移动这些节点，无需逐帧改轮廓。
- 建议使用父坐标系中的旋转锚点：身体 `(274, 260)`、耳 `(290, 83)`、双眼 `(368, 114)`、尾 `(274, 340)`。CSS 预览使用各部件的包围盒锚点近似；原生实现可直接使用这些坐标。

## 八个状态

| 状态 | 时长 | 循环 | 优先级 | 角色表现 | 减少动态时 |
|---|---:|---|---:|---|---|
| `idle` 待命 | 7200 ms | 是 | 0 | 身体静止，每轮仅短暂眨眼 | 放松睁眼 |
| `working` 工作中 | 3200 ms | 是 | 20 | 视线略向下，尾巴轻扫 2° | 向下看，静止 |
| `thinking` 思考中 | 4800 ms | 是 | 20 | 向上看，折耳轻动 | 向上看，静止 |
| `success` 已完成 | 900 ms | 否 | 40 | 一次小点头、开心闭眼，闪出一次短光线 | 开心闭眼，无光线 |
| `attention` 需要你看看 | 1200 ms | 否 | 60 | 耳朵抬起，头略偏 2°，随后保持 | 抬耳睁眼 |
| `error` 遇到问题 | 450 ms | 否 | 80 | 耳朵垂一下、眼睛略收窄 | 垂耳、窄眼 |
| `sleep` 休息 | 5200 ms | 是 | 5 | 闭眼，身体呼吸缩放低于 1% | 闭眼静止 |
| `greeting` 你好呀 | 1100 ms | 否 | 10 | 尾巴挥一次、身体轻偏 3° | 友好睁眼 |

待命眨眼时长 180 ms。工作中和思考中同样只保留稀疏眨眼，不让精灵一直蹦跳。成功与打招呼只播放一次；真实业务在结束后切回持续状态。预览为了比较表情，会停在该状态，直到点击下一状态，并明确标记单次动作已结束。

## 状态调度

1. 真实任务开始才能显示工作中；真实 AI 请求待返回时才显示思考中。动画本身不代表进度，也不随机切换任务状态。
2. 高优先级事件可打断低优先级事件。`working` 与 `thinking` 由实际任务生命周期替换；发生错误立即打断，等待用户处理。
3. 错误与待确认保持到用户处理。成功后返回之前的持续状态；初次打招呼结束返回待命。当前有任务时，休息和打招呼均不介入。
4. 连续同类事件合并，不排成长串动画。高频保存、打字、流式 token 不重复触发成功或问候。
5. 角色离屏、应用在后台且不可见时暂停，恢复时直接采用当前业务状态。避免让不可见动画消耗资源。

## 在终端和其他位置使用

- 终端标题栏预留 24–32 px 的配件位，和文字状态一起出现；32 px 才开始播放部件动作。16 / 24 px 使用静止姿态，避免细节颤动。
- 不遮挡输出、不插入终端字符、不影响输入焦点和选区，不把角色放在可执行命令的位置。点击需要用户处理的状态时，未来可打开原有任务详情。
- AI 问答页可用 48–64 px 角色表示等待；无任务时保持安静。空状态或首次欢迎可使用 96–160 px 的完整表演。
- 全 App 同一可见区域只放一个活跃角色。关闭陪伴动画后，仍保留文字状态，不能通过角色表情单独传递错误或完成。
- 错误表现不抖屏、不摇晃窗口、不红闪；底色变化不承担状态语义。

## 减少动态与资源约束

默认读取系统 `prefers-reduced-motion`，用户也可手动开启。开启后停止全部关键帧与过渡，保留每个状态的静态表情和文本。暂停按钮冻结当前动画时间，不取消真实任务。小于 32 px 的示例始终静止。

预览是无依赖 HTML，内置与 SVG 相同的图形节点和与 JSON 一致的参数，避免 `file://` 下的 `fetch` 限制。SVG / JSON 是后续原生实现的资源契约；预览中的 CSS 动画不会自动接入 SwiftUI 或终端任务。

## 建议的下一步接入

先在 App 的已有标题栏或 AI 状态位放 32 px 静态精灵，并让真实任务状态驱动 `idle → working/thinking → success/error`。确认不影响键盘和文字布局，再逐步开启动作。保持当前 SVG 的部件名称，后续可映射到 SwiftUI 分层变换或其他渲染器，无需重做角色设计。
