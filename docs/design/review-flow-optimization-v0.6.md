# 逐个验收视觉交互与动画优化方案

日期：2026年10月18日  
状态：已评审（2026-10-18）。P0 与部分 P2 已落地（aeb882c、51f89dd）；**P1 不采纳**，P3 暂不做，理由见 [产品方向](../direction.md)。P1 中只采纳两点：提交框写明本次不包含的改动，当前处滚出视野时显示「回到当前处」。  
范围：逐个验收主流程，以及与提交、撤销、阅读提示相关的视觉和动画。本文不实施功能。

建议先把操作目标、确认状态和恢复路径做可靠，再交付专注验收及连续反馈，随后统一视觉密度和主题细节。保留现有原生面板、普通全部改动、阅读与源码分离、四套主题及多终端。

用户应始终能回答三个问题：现在处理哪一处，这次动作会改变什么，反悔后能恢复到哪里。

## 优先级与交付顺序

| 优先级 | 优化内容 | 交付结果 | 前置条件 |
| --- | --- | --- | --- |
| P0 必须先满足 | 状态身份、操作范围、成功读回、撤销保护、快捷键与显示一致、防连续回车误提交 | 确认与 Git 实际内容一致，错误不冒充完成，操作可恢复 | 本轮已发现问题的对应回归场景通过 |
| P1 主流程 | 专注验收、待定队列、局部处理、稳定进度、提交汇总、操作后的连续反馈 | 连续处理多处时目标清楚、位置稳定，能完成或安全中断一轮 | P0 门槛满足 |
| P2 视觉与动画统一 | 减少重复提示、提交区按需展开、主题语义、阅读更新提示、终端命名、减弱动态效果 | 四主题浅深色下主次一致，内容和控件可辨认 | P1 流程稳定 |
| P3 后续增强 | 可检查的操作历史、按 AI 批次回看、批次摘要 | 能按原分支、文件及时间定位操作，检查恢复影响 | P0 的可信快照与记录持久化边界明确 |

P0 是实施验收门槛。当前工作区已有并行修复，不在本文中重新判定其完成状态；已有修复可用同场景的新鲜回归证据解除门槛，不必重复实现。

第一批建议交付 P0 和 P1。P2 中阻挡操作的可读性问题应同时处理，包括推送命令被截断、提示遮挡正文、错误的快捷键说明。P3 先保留方案，不纳入第一批。

## 流程与页面结构

### 保留两种浏览方式

“全部改动”继续适合自由滚动、多文件对照和按行选择。新增“专注验收”作为同一批改动的另一种查看方式，通过现有“逐个验收”入口进入，首次默认使用专注方式，之后记住用户选择。

两种方式共用改动身份、处理决定、选择范围和撤销记录。切换视图不改变 Git 内容、不重置进度，并定位同一处；找不到同一处时明确提示内容已更新。

### 专注验收的布局

| 区域 | 固定展示 | 收起或按需展示 |
| --- | --- | --- |
| 顶部 | 项目与分支、本轮进度、待定数量、视图切换 | 全套快捷键放到快捷键一览 |
| 当前处标题 | 文件路径、工作区或暂存区、风险原因、操作范围 | 路径中间省略，悬停和复制可取得完整路径 |
| 内容区 | 当前改动及必要上下文，已选行清楚标识 | 相邻已处理处折为结果摘要；允许展开上下文 |
| 底部操作条 | 当前处对应的收下、待定、丢弃或退回操作 | 解释、评论、编辑放在次级动作区 |
| 侧栏 | 文件导航、Git 分组、当前文件与区域 | 提交框默认折为摘要，新手引导放在侧栏 |

当前处对齐到内容区上方约四分之一处。超长改动允许内部连续阅读，处理动作不得因滚动离开屏幕。用户手动滚动查看其他内容时，显示“返回当前处”，不会偷偷改变键盘动作的目标。

当前处正文完全离开视口后，停用 Enter、Delete 和底栏的写操作，显示“返回当前处后操作”；返回按钮只恢复定位，不顺便执行。超长块仍有正文可见时可继续阅读和处理，但固定标题必须明确文件与范围。点击另一处标题可以显式切换目标。

点击另一处标题，才把它设为当前处；滚动经过不自动确认。点击“收下选中行”之前，底部明确显示选中行数。跨块选择时第一批禁用逐处快捷动作，提示先缩小到单块或使用已有明确的整文件操作。

右下角新手卡移入侧栏，避免遮住代码。完成步骤后折成一行“已完成引导”，不推动差异正文重新布局。

### 从进入到退出的一轮验收

1. 进入时读取当前状态，建立本轮队列，显示“8 个文件，12 处待确认”。未完成读取时保留上次画面或稳定占位，暂不开放写操作。
2. 初始排序沿用风险优先，同风险下保持文件与原始位置顺序。已暂存内容也进入待确认队列。
3. 定位第一处，展开完整的当前操作范围；高风险文件同时说明原因，例如“环境文件，可能包含凭据”。
4. 用户选择收下、待定、丢弃，或仅导航、评论、编辑。只有成功完成处理才推进已处理数。
5. 成功后原位置先出现结果，再定位下一处待确认；失败则保持目标和选择，显示原因与恢复入口。
6. 普通待确认队列结束后，显示“已处理 10 处，还有 2 处待定”，提供“处理待定”“检查提交内容”“保存进度并退出”。
7. 提交前单独核对实际暂存内容、未确认项和本次不包含的工作区内容，进入独立提交汇总。
8. 提交后展示提交编号和待推送数量，用户主动打开交付预览并执行推送。退出验收也可保留进度和所有尚未处理的内容。

再次进入时恢复同仓库、同分支的未完成验收。提交成功或主动选择结束本轮后，封存本轮结果；下一轮根据当前 Git 状态建立新队列。工作区保留的内容会成为下一轮待确认，不把上一轮决定永久当作未来版本的确认。

进入验收后不自动重排正在处理的队列。新出现的高风险改动放入新增队列并提示“新增 2 处，其中 1 处高风险”；用户可跳过去，当前操作的位置和目标保持稳定。

## 状态定义与动作语义

### 把阅读记录与处理决定分开

| 维度 | 状态 | 使用规则 |
| --- | --- | --- |
| 阅读记录 | 未标记、标记看过、内容已变化 | 可手动记录，仅作回看参考，不计为已处理 |
| 处理决定 | 待确认、待定、已收下、已丢弃、已退回 | 决定本轮处理进度与提交资格 |
| Git 位置 | 工作区、暂存区、部分暂存 | 从实际 Git 状态读取，不由界面勾选推测 |
| 操作过程 | 空闲、处理中、失败、因版本变化而暂停 | 控制当前动作能否执行，不伪装成处理决定 |

主画面只突出处理决定和 Git 位置；阅读记录放在次级信息中，避免每处堆四排标签。“看过”不代表同意提交，“已暂存”也不代表已确认。

“需要重新确认”表示受影响部分回到待确认，同时保留其原决定和变化原因供回看。部分选行处理时可派生“部分处理”，剩余内容仍待确认。

### 根据当前范围改变动作文字

| 当前对象 | 收下动作 | 次级动作 | 对应结果 |
| --- | --- | --- | --- |
| 工作区中的可部分处理改动 | 收下这处并暂存 | 待定、丢弃这处 | 暂存成功并读回后，当前版本已收下 |
| 暂存区中的改动 | 确认提交这处 | 待定、退回工作区 | 确认动作核对当前暂存版本，不重复暂存 |
| 单块中选中的部分行 | 收下选中的 N 行 | 清除选择、待定当前处 | 仅所选行完成，剩余行继续待确认 |
| 新文件或不能部分处理的文件 | 收下整个文件 | 待定、明确的整文件丢弃 | 动作之前持续显示“整文件操作” |
| 二进制或无法完整显示的文件 | 查看文件后确认整文件 | 查看原文件、待定 | 不从看不见的部分生成逐行确认 |

取消“不要”这种跨区域含义变化的主文案。工作区显示“丢弃这处”，暂存区显示“退回工作区”；二者的图标、提示和操作记录也使用同样的名称。

“退回工作区”表示已经决定不把这部分纳入本次提交，计入本轮已处理；内容保留，但不再自动生成本轮待定条目。待定表示本轮尚未作决定，仍计入未处理。用户可从退回结果主动选择重新纳入验收，使它回到待确认。

退回时若与原有工作区改动合并，原有工作区待确认项继续存在。只有可以准确映射的范围保留原决定，其余显示需要重新确认及原因，不能把原有工作区内容一起算作已退回。

对新文件、二进制、不能部分处理的文件，以及原本选行但实际只能整文件处理的情况，必须先明确整文件范围。丢弃整文件先展示文件名与范围确认；无法建立可信恢复记录时停用丢弃入口并说明原因。

评论与 AI 解释都不改变处理决定。AI 解释失败时保留评论、选择与当前处，用户仍可继续人工验收。

### 状态转换表

| 当前状态与事件 | 处理过程 | 成功后的状态 | 失败或内容变化时 |
| --- | --- | --- | --- |
| 待确认的工作区改动，收下 | 锁定当前仓库、分支与内容版本，暂存，再读回 | 对应版本已收下，Git 位置为暂存区 | 保持原决定，停留当前处，提供重试 |
| 待确认的暂存改动，确认 | 核对当前暂存内容仍与所见一致 | 当前暂存版本已收下 | 显示需要重新确认，不自动覆盖 |
| 待确认，选择待定 | 保存待定决定，不改 Git | 待定，转入待定队列 | 保存失败时保留当前界面并提示，不假装已保存 |
| 工作区改动，丢弃 | 先取得可恢复快照，再应用丢弃并读回 | 已丢弃，保留操作摘要和恢复入口 | 保持当前处；不能恢复时不执行 |
| 暂存改动，退回工作区 | 取消暂存并读回 | 已退回，本轮已处理；保留内容且不进入本次提交，可主动重新纳入 | 维持原确认与位置，显示失败 |
| 已收下，手动标为待验收 | 清除对应提交确认，不改变 Git 位置 | 待确认，暂存内容仍在 | 不把它当作撤销暂存 |
| 已处理，撤销成功 | 恢复 Git 内容、位置与对应决定 | 回到该次动作之前，定位被恢复处 | 失败保留操作记录与重试入口 |
| 已处理内容被外部修改 | 只核对受影响版本与范围 | 受影响部分需要重新确认，其他部分保留 | 映射不确定时要求重新确认，不猜测对应关系 |

动作成功、Git 读回成功和记录更新完成之后，再显示完成反馈。暂存或丢弃失败时，不增加进度、不增加成功统计、不自动跳到下一处。

### 部分暂存与重复文本

同一个文件在暂存区和工作区的两处内容独立确认。相同空行或相同文本也可能属于不同改动，不能只靠文件路径和文本判断为同一处。

改动身份应在暂存、取消暂存、分块合并和上下文位移后延续。需要同时区分仓库工作树、完整分支身份、基准版本、内容版本与同文本的具体实例。具体算法在实施设计时决定，以本方案的行为验收为准。

部分收下的示例：一处有 5 行待处理，选 2 行收下后显示“已收下 2 行，剩余 3 行待确认”。整处尚未完成，进度不加一；直到所有剩余部分被收下、丢弃或明确退回后，才完成该处。不能因为某些行收下就把整块标为看完。

### 稳定的进度口径

主进度显示“已处理 3 / 12 处”，其中已收下、已丢弃、已退回合计为 3；另显示“待定 2 处”，待定包含在剩余 9 处中。进度条不把“只是看过”算作完成。

本轮建立的队列条目保留到本轮结束。收下后块合并、丢弃后差异消失，都不让已处理条目从分母中消失。按部分行操作不自动增加本轮分母，条目内展示剩余范围。

外部新增、删除或改写内容需要调整队列时，明确显示变化，例如“新增 2 处，已处理 3 / 14”“外部移除了 1 处，已从本轮移出”。外部删除不计为用户已处理；旧内容被替换时保留历史结果，新的版本重新待确认。

撤销成功或外部内容变化，可能使已处理数下降；同时展示“恢复了 1 处待确认”等明确原因。普通暂存、块合并或刷新不能使完成数无故倒退。

旧版“已看”记录可以提示“上次看过，尚未确认”，不得直接迁移成可信的已收下。存在重复文本等映射歧义时，重新确认受影响内容。

## 键盘与焦点

下表中的逐处单键与提交规则限定于专注验收。会话激活时，从侧栏提交按钮、菜单或快捷键发起提交，都进入同一份汇总校验，不允许绕过未确认暂存内容。用户主动保存进度并退出验收后，普通提交入口恢复其原有明确的 Command Enter 行为；自由浏览全部改动不强行启用验收会话。

| 输入 | 默认行为 | 约束 |
| --- | --- | --- |
| 空格、Shift 空格 | 下一处、上一处待确认 | 只导航，不记录已看或已处理；普通队列末尾停住，不自动循环待定项 |
| j、k | 按队列顺序移动 | 允许回看已处理摘要；不改变决定 |
| Enter | 执行当前处明确显示的收下动作 | 只在验收画布拥有焦点且动作可用时生效 |
| Delete | 执行当前处明确显示的丢弃或退回动作 | 整文件破坏性操作走范围确认；输入框内继续删除文字 |
| u | 标为待验收 | 清除对应确认，不撤销 Git 操作；按钮提示写明区别 |
| c、e | 评论、编辑当前处 | 返回后定位原处并重新核对内容版本 |
| Option Command Z | 撤销最近的 Git 操作 | 所有页面提示一致；Command Z 留给文本撤销，验收画布显示明确的 Git 撤销按钮 |
| Command K | 全局搜索 | Markdown 插链接改用无冲突按键；不再消费全局搜索快捷键 |
| Command Enter | 提交汇总页执行提交 | 仅当汇总页已激活、提交条件满足时生效；编辑说明期间普通 Enter 用于换行 |

正在处理时，来自键盘的其他写动作不排队，也不重放到下一处。忽略按键自动重复；一次收下之后，必须松开 Enter 并再次按下，才能处理另一处。

最后一处处理完只进入汇总或待定结果页，普通 Enter 不变成提交。即使一直按住 Enter，也不能创建提交。切换到终端、评论框或编辑器后，逐个验收的单键操作全部暂停；画布边框和操作条显示当前焦点所属。

全局快捷键冲突先在现有菜单与编辑器命令中核对。插链接的新快捷键在实施前对账后确定，不在方案中凭空占用另一组现有按键。

P1 的所有主动作必须具备可读名称、默认激活动作和明确焦点顺序。当前处变化、成功、失败及待定结果提供一次简短辅助功能播报；不因动画关闭而缺失。这些属于主流程可操作性，P2 再补齐八种主题与完整 VoiceOver 场景矩阵。

## 提交汇总与完成状态

### 提交前明确包含和不包含的内容

汇总页展示实际暂存文件数、待提交改动、未确认的暂存内容、保留在工作区的待定内容、明确排除本次提交的已退回内容，以及提交说明。待定与已退回分别计数，不重复计入未处理。用户可从任一项返回对应差异。

已暂存但待定或未确认的内容阻挡专注验收流程中的提交。提供“继续确认”“移出本次提交”两个明确动作；后者显式取消暂存、保留工作区内容并支持撤销，不能在进入汇总时自动执行。

未暂存的待定内容可以留在工作区。汇总页明确写“本次不包含 2 处待定改动”，由用户主动选择只提交已确认的暂存内容，不把它描述为全部工作完成。

提交检查显示“检查中”“需要确认”“检查通过”或“检查失败”。检查中和失败时不能直接放行；风险确认绑定这份暂存版本，版本变化后原确认失效。AI 提交说明失败不阻挡用户手写，但不能绕过提交检查。

本方案保留普通提交的现有入口，不新增全局强制逐处审阅政策。普通流程仍受统一的提交安全检查约束；专注验收中的未确认项不得悄悄进入本次提交。

### 完成与中断的文案

| 实际状态 | 主文案 | 主动作 |
| --- | --- | --- |
| 本轮处理完成，暂存内容均已确认 | 本轮已处理完，准备提交 | 检查并提交 |
| 暂存已确认，工作区仍有待定内容 | 本次可提交，另有 N 处待定 | 检查本次提交、继续待定 |
| 已提交，尚未推送 | 本地已提交，还有 N 个提交未推送 | 预览推送 |
| 工作区为空，但仍有收起的改动 | 工作区已清空，另有一批暂放改动 | 继续那一批 |
| 已处理、已提交且无待推送、待定或暂放内容 | 本轮已完成 | 查看本轮记录 |
| 推送失败 | 本地提交已保留，推送未完成 | 查看原因、重新预览 |

推送计划优先固定展示仓库、远端、目标分支和锁定提交，完整命令另放可复制区域。默认从左上角显示；长命令支持换行。预览后参数或提交变化，计划失效并要求重新预览。

日统计放在完成状态的次级信息中；不让“工作区暂时干净”直接触发已交付庆祝。

## 动画与连续反馈

以下时长为建议的设计初值，需要用实际设备与录屏调校，不代表现有测量结果。沿用现有 Motion 命名和四主题适配，避免新增一套独立动效系统。

| 触发 | 建议反馈 | 时长初值 | 状态与焦点要求 |
| --- | --- | --- | --- |
| 按钮按下 | 轻微压下；像素主题位移一格 | 80–120 毫秒响应 | 立即响应输入，但不提前显示成功 |
| 操作耗时超过短等待 | 按钮文字变“暂存中”等；保留当前正文 | 约 150 毫秒后显现等待 | 不整页换成空白或大加载界面 |
| 收下成功 | 原位置出现勾选和“已暂存”或“已确认” | 约 180 毫秒 | 先读回成功，再出现结果 |
| 自动继续 | 旧处折为摘要，下一处接到相同阅读位置 | 约 180–240 毫秒 | 每次操作至多一次自动滚动；跨很远的文件用短淡入，避免长距离飞移 |
| 待定 | 状态改为待定，待定数量更新 | 约 120–180 毫秒 | 不用绿色勾选或完成音效 |
| 丢弃或退回成功 | 显示明确结果摘要与撤销入口 | 约 180 毫秒 | 不做碎裂或抛出动画，不暗示不可恢复 |
| 撤销成功 | 恢复到受影响处并短暂强调恢复范围 | 约 180–240 毫秒 | 不跳到另一处开始自动处理 |
| 外部更新 | 新增提示占位，变化范围短暂着色 | 着色约 600–900 毫秒 | 保持阅读锚点，不靠闪烁表示高风险 |
| 卡片拖动 | 尺寸随手移动，松开后轻微到位 | 拖动实时；松开约 240 毫秒 | 终端和差异画布同步调整尺寸 |
| 进入汇总 | 内容交替，操作条更新用途 | 约 180–220 毫秒 | 不把动画完成事件当作提交触发 |

结果与下一处的过渡以稳定内容位置为准。首次实现优先使用原位结果、折叠和短淡入，不制作跨面板飞行的文件副本；如果实际屏幕位置无法可靠对应，就使用静态“已移入暂存区”提示。

动画可被后续明确输入打断，界面始终呈现最新已确认状态；不因展示动画额外锁住已经完成的 Git 操作。无法处理的输入即时说明原因，不积压到下一处执行。

开启减弱动态效果时，关闭位移、缩放、弹性、呼吸、滚动动画和分隔条淡入，直接切换到结果。进度文本、错误、恢复结果和辅助功能播报继续存在。主题切换和玻璃效果不改变这条规则。

## 视觉规则与相邻体验

### 统一三个强调层级

当前处使用一条强调色标记与轻背景；风险标签只说明风险；卡片边框使用较弱的中性色。已处理内容折为摘要，展开后仍保持正常可读对比，不通过极低透明度把文字变得难以辨认。

焦点边框只表明哪个面板接收键盘输入。文件选中填色、处理结果图标和风险色各有独立含义，不用整圈高饱和边框同时表达所有状态。

| 控件 | 推荐初值与约束 |
| --- | --- |
| 当前文件与主操作文字 | 约 13–14 pt，主次靠字重和位置区分 |
| 辅助信息 | 约 11–12 pt，不再叠加多排极小提示 |
| 主操作 | 高约 32 pt；只在当前处保留一个最强主动作 |
| 图标操作 | 建议至少 28×28 pt 有效点击范围，提供名称与键盘可达入口 |
| 字体 | 保留用户的代码字体与字号；像素界面使用已有 12/24 pt 体系，正文和代码保持正常字体 |
| 窄窗口 | 首次没有用户偏好且内容区不足约 760 pt 时，可默认单列；已有并排偏好不覆盖，提供明确切换 |

同一含义在四套主题浅深色下保持同样的图标、文字和位置。像素主题的粗边框与底纹弱于当前改动；水磨石颗粒避开按钮文字区域。禁用态必须和可用态明显区分。

视口较小时先减少辅助信息、折叠提交框和相邻处，不擅自关闭用户的终端或改写已保存布局。可提供一次性的“临时专注当前面板”，退出后恢复原布局。

### 阅读提示和终端标签

外部更新提示放在阅读工具条下，占据真实布局高度；可折为“外部更新 1 段”，提供下一处更新与查看差异。更新前后保留正在阅读的段落锚点，标题和正文不能被覆盖。

终端默认名称包含当前目录与 shell，例如“docs · zsh”“repository · zsh”，同名时增加序号。用户自定义名称优先，不自动覆盖；辅助功能名称包含标签编号和完整目录。

### 操作历史的后续形态

P3 增加紧凑的最近操作抽屉，每项显示动作、原分支、文件数、时间和恢复可用性。失败或冲突记录继续留在原处，提供查看差异和重试。

历史 AI 批次只有具备可信的开始和结束快照时才提供整批撤回。缺少结束快照时可回看已有记录，不能把当前文件补拍成旧批次结束状态。

持久化整份恢复内容涉及容量、隐私和保留周期，另作实现设计；本次不承诺跨重启可恢复任意丢弃内容。普通验收进度和待定决定需要跨重启保留，但每次恢复都要重新验证内容版本。

## 验收场景与观察方法

所有 Git 写操作在新建演示或临时仓库执行；先记录文件、暂存区与分支状态，再操作和读回。动画用录屏逐帧观察，运行结果与观感分别记录。

| 场景 | 预期结果 | 验证方式与优先级 |
| --- | --- | --- |
| 暂存操作失败 | 决定、进度、成功统计不变，仍在原处，可重试 | 注入失败并核对 Git 与界面；P0 |
| 同文件两区新增相同空行 | 只确认目标处，另一处仍待确认；合并暂存后进度不倒退 | 实际 Git fixture；P0 |
| 收下选中的 2/5 行 | 仅两行进入暂存区，剩余三行仍可操作，整处未完成 | 编辑→暂存→读回；P0 |
| 同一 SHA 切换到另一分支再撤销 | 不修改错误分支；明确说明原操作所属分支 | 校验两个分支 OID；P0 |
| 历史 AI 完成后又有人工修改 | 回看可用；没有可信快照时不能覆盖人工内容 | 关闭期间更新再重开；P0 |
| 安全检查尚未完成时提交 | 显示检查中，不创建提交；当前版本检查完成后再判断 | 检查延迟与版本变化场景；P0 |
| 撤销被后续外部改动阻挡 | 文件不被覆盖，记录仍在，处理冲突后可重试 | 内容与操作记录读回；P0 |
| 搜索后结果变化 | 可见标题、辅助功能名称与执行命令一致 | 输入、选择、执行、读回；P0 |
| Markdown 输入焦点下 Command K | 打开全局搜索，文档正文和脏状态不变化 | 快捷键与编辑缓冲区核对；P0 |
| 最后一处长按 Enter | 进入汇总，提交次数为零，松键不会补发提交 | 自动重复按键场景；P0 |
| 操作中连续按 Enter | 仅当前处操作一次，不在下一处重放 | 慢 Git 与键盘重复输入；P0 |
| 当前处正文已滚出视口 | Enter、Delete 和底栏不修改内容，不增加进度；返回当前处只定位 | 手动滚动后分别触发；P0 |
| 不支持逐行操作的文件 | 动作前清楚标明整文件范围，没有静默扩大 | 新文件、二进制、超显示预算；P0 |
| 连续 Space 导航 | 不改变确认数，不在普通队尾反复循环待定 | 有待定与已处理条目的队列；P1 |
| 连续处理十处 | 没有空白帧或重复跳转，每次最多一次自动定位 | 带帧时间的录屏；P1 |
| 工作区待定与暂存区待定并存 | 汇总区分不包含内容；未确认暂存内容不能混入提交 | 提交前后实际 index 对照；P1 |
| 验收中从侧栏或菜单提交 | 仍进入相同汇总校验；明确退出验收后普通提交恢复 | 三种提交入口逐个核对；P1 |
| 已确认暂存后，工作区又被修改 | 原暂存版本未变化时保留其确认，新工作区版本单独待确认 | index 与工作区分别改动；P1 |
| 验收中新增高风险文件 | 当前目标不被抢走，显示新增提示，可主动跳转 | 外部写入 .env；P1 |
| AI 或外部工具修改当前版本 | 只使受影响部分需要重新确认；原操作不作用于新版本 | 操作前后插入外部更新；P1 |
| 部分丢弃后撤销 | 内容、Git 位置与处理决定一同恢复，定位正确 | 丢弃→撤销→读回；P1 |
| 重启后继续待定 | 待定仍在；内容已变化的项提示重新确认 | 同配置重开并修改部分文件；P1 |
| 长路径推送预览 | 不滚动即可看到远端、分支、提交；完整命令可复制 | 最小窗口及长路径；P1 |
| 已暂放一批改动 | 显示暂放状态，不显示全部工作已交付 | 收起→空状态→恢复；P1 |
| 外部更新阅读文档 | 标题和正文无遮挡，位置稳定，可定位更新段落 | 长文中段外部更新；P2 |
| 减弱动态效果开启 | 所有对应动效直接切换，键盘和结果播报可用 | 系统设置与录屏；P2 |
| 四主题乘浅深色 | 所有状态可辨认，像素字不溢出，水磨石文字清楚 | 八种主题检查当前处、错误、汇总与弹窗；P2 |
| 最小窗口和大字号 | 主动作可见，文本可读，不自动破坏面板布局 | 1080×680 pt 与用户字号 18；P2 |
| VoiceOver 与全键盘 | 可激活当前处、主动作、待定和恢复；状态变化有名称 | 实际开启 VoiceOver；P2 |

P0 全部通过才能验收 P1 的写操作流程。P1 验收完成后，再评价动画节奏与视觉密度；只展示一个漂亮静态画面不算流程完成。

## 实施对照与评审顺序

| 方案部分 | 现有入口与模块 | 后续实施关注点 |
| --- | --- | --- |
| 当前处、导航、专注方式 | AllChangesView.swift、ReviewViews.swift | 按稳定改动身份定位，保留普通全部改动 |
| 收下、丢弃、待定与进度 | ReviewFlow.swift、ReviewProgress.swift | 决定与 Git 结果分开，部分处理和旧记录兼容 |
| 快捷键 | FolmiApp.swift、EditorTextView.swift | 全局/输入框作用域对账，重复按键保护 |
| 撤销与历史 AI | UndoSteps.swift、AIActivity.swift | 分支身份、可信快照、失败记录保留 |
| 提交与交付 | CommitCheck.swift、ChangesCard.swift、DeliverySheet.swift | 当前暂存版本检查、独立汇总与可读预览 |
| 视觉与动画 | DesignTokens.swift、PaneLayout.swift、ThemeViews.swift | 共用现有 token，减弱动态效果完整覆盖 |
| 阅读与终端 | FileEditor.swift、TerminalPane.swift | 提示占位、阅读锚点、默认名称 |

评审时先确认三个产品选择：收下与暂存的关系、待定内容怎样退出本轮、专注验收何时允许提交。随后评审当前处布局和状态转换，再评审动画时长与主题细节。本文给出了推荐默认规则，未列出互相冲突的备选流程。

首批完成的标准是：用户可以连续处理十处、保留待定、从失败恢复，并明确知道这次提交包含什么；全过程没有状态提前完成、目标漂移或按键误提交。通过这些场景后，再考虑 P3 的历史抽屉和批次增强。

依据：本会话的 v0.6 只读审查与截图，以及现有 AllChangesView、ReviewFlow、ReviewProgress 等模块。现状证据与本方案的推荐行为分开：P0 门槛引用历史发现，其是否已被并行修复需按对应场景重新验收。
