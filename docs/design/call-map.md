# 调用关系：这处改动牵连到哪

日期：2026年10月26日
状态：**第一步已做，其余是设计。** 样式稿见 [call-map-mockup.html](call-map-mockup.html)。

## 已经做了：以方法为中心看上下游（2026-10-26）

按反馈调整了顺序：先做「检查一个方法」，接口配对往后放。

- **怎么打开**：编辑器里光标放在函数名上（定义处或调用处都行），按 ⌃⌥H，或右键「查看调用关系」；⌘K 搜「调用关系」；页面右上角可以直接搜函数名。没选中心时，页面列出被调用最多的函数。
- **两种看法**：「上下游」是左右两棵树，左边谁调用它、右边它调用了谁，每一层都能展开，递归处标 ↺；「关系图」把中心放在中间，往左两层调用方、往右两层被调用的，每列最多 12 个。点任何一个都会以它为中心重新展开，⌫ 或左上角的按钮后退。每行右边的位置可以点，调用方打开到调用那一行，被调用的打开到定义。
- **语言**：JS、TS（含 JSX/TSX、`.vue` 里的脚本）、Python。
- **别名**，都能跟过去：
  - `import { a as b }`、`import * as ns`、默认导出、`export { a as b } from`、`export * from` 组成的 barrel 文件；
  - CommonJS 的 `require`、解构的 `require`、`module.exports = { a, b: c }`、`exports.x =`；
  - 路径别名：tsconfig / jsconfig 的 `paths` 和 `baseUrl`（支持 `extends`、注释、尾逗号），vite / webpack / vue.config 的 `alias`，没配置时按惯例认 `@/` 和 `~/`；monorepo 的工作区包按 `package.json` 的 `name` 认；
  - 重新命名：`const h = foo`、`const h = utils.foo`、`foo.bind(this)`、`const { a: b } = ns`，Python 的 `h = foo`、`import a.b as m`、`from m import f as g`、`from . import x`、`from x import *`；
  - 成员：`this.x()` / `self.x()` / `super.x()` / `super().x()`、父类的方法，以及能看出类型的成员：TS 的 `constructor(private svc: Service)`、带类型的字段、`this.svc = new Service()`，Python 的 `self.repo = Repo()` 和 `def __init__(self, repo: Repo)` 加 `self.repo = repo`，局部的 `const svc = new Service()`、`svc = Service()`。
- **不只是调用**：JSX 里的 `<OrderSummary />` 算「渲染」，`onClick={save}`、`router.get('/x', handler)` 这类把函数当参数传的算「传入」。顶层传给调用的匿名函数按调用命名，比如 `router.get("/orders/:id")`；`const save = useCallback(() => …)`、`computed(() => …)` 按变量名命名。
- **说清楚有多准**：对象类型看不出来时（`obj.save()`），按方法名去找类的方法，最多 3 个候选，标灰字「可能」；`get`、`map`、`then` 这类太常见的名字不猜。`console`、`print`、`fetch` 这类内置的不列；外部包标「外部」。没找到调用方时写「没找到，不代表没人用」。
- **快**：后台读，不卡界面；文件按大小和修改时间缓存，项目状态变了才重读，只重读变了的文件。超过 1 MB 或压缩过的文件跳过。本机几个真实项目：1085 个文件首次 1.1 秒，之后 0.7 秒；300 个文件 0.5 秒左右。
- **不记状态**：图只在内存里，项目里不多出任何文件。按磁盘上的文件算，编辑器里没保存的改动不算。

## 已经做了：改动卡片上的「影响」（2026-10-26）

- 逐个验收里，JS / TS / Python 文件的差异上方一行：「影响  loadInvoice 被 3 处调用  formatTotal 没找到调用方」，最多列 4 个函数，再多写「等 n 个函数」。「处」按调用所在的行数算，只按方法名对上的另写「n 处可能」。鼠标停上去列出调用它的函数，点一下进调用关系页，以它为中心。
- 改了哪些函数：差异里新增的行落在哪个函数里（取最里层的）；只删不加的地方，删除处前后两行在同一个函数里才算，所以整个删掉一个函数不会算到旁边的函数头上。路由回调这类匿名入口不列。
- 暂存区的差异如果工作区还有改动，行号和磁盘上的文件对不上，不显示；删除的文件不显示。
- 调用图在打开逐个验收、而且改动里有这三种文件时在后台读；大仓库模式下不自动读。
- 删掉和改名的函数（2026-10-26 做了）：读改动前的那一版文件（工作区的改动对暂存区，暂存区的改动对 HEAD），找出它有、现在没有的函数；把这一版放回调用图、整个项目重新连一遍，其他文件里还能连到它的调用就是「还在用旧名字」的地方。已经改成新名字的调用连不到旧函数，自然不算；同一个文件里的调用是改动前的代码，不算。同一个类里少了几个、多了几个一样多的函数，按顺序配成「改名为」。标红排在最前，点开列出每一处。每个文件要重新连一遍（一千个文件约半秒），一次最多算 20 个文件。
- 参数变了（2026-10-26 做了）：大纲里记下每个函数的参数表（名字、有没有默认值或 `?`、`...rest` / `*args`、Python 的仅限关键字参数和 `**kwargs`，方法的 `self` / `cls` 不算），每处调用记下实参（几个位置参数、哪些关键字、有没有展开）。改动前后同名函数的参数表不一样时，用新的参数表逐处检查现在的调用：少了必填的、多了（没有 rest 时）、关键字名不存在（没有 `**kwargs` 时）。只看个数和名字，不看类型；展开传参的看不出，单独计数。改了 `constructor` / `__init__` 时，检查创建这个类的地方。`Base.__init__(self, x)` 这种用类名直接调方法的写法，第一个实参算作 `self`。
- 在本机 4 个真实项目上，拿现在的代码检查约 2 万处能查参数的调用：判成对不上的有 10 处（多是 JS 里少传参数的合法写法）。「影响」只在参数真的改了时才显示，所以这些不会冒出来。为此修了三处：同一个文件里同名的嵌套函数和局部变量按位置区分、包了一层的函数不记参数、单行的打包产物跳过。
- 还没做：参数类型变了、返回值变了。

下面原来的设计（接口配对、下游到表和任务、关联项目）是后面几步。

## 要解决什么

AI 一轮改了一个接口（改了参数、改了返回、改了它写的表），验收的人要知道：

- **往上**：前端哪些功能在用这个接口，会不会跟着坏。
- **往下**：服务端这个接口最后落到哪：调了哪些函数，发了哪些后台任务，读写了哪些数据库表。

## 先对一遍原则

- **这不是 IDE。** `direction.md` 写了 LSP 不做。这个功能不做「跳到定义」「重构」，只回答验收时的一个问题：**这处改动牵连到哪**。所以主入口在改动卡片上，不在编辑器的右键菜单里。
- **前后端之间本来就没有调用关系。** 前端 `fetch('/api/orders/' + id)` 和后端 `@app.get("/api/orders/{id}")` 之间只有一个 URL 字符串，LSP 也连不起来。所以「接口」这一层只能靠认路由和认请求的写法，这是这个功能的核心，也是 LSP 给不了的部分。
- **不在 Git 之外另记状态。** 关系图从项目文件现算，放内存；缓存按文件内容的哈希存在 App 数据目录，删了重算。项目里不多出任何文件。
- **说清楚有多准。** 静态认出来的关系一定有漏的（动态拼的 URL、依赖注入、反射）。每条关系标「确定」或「可能」，没找到调用方时写「没找到，不代表没人用」，不写「没人用」。
- **快是硬指标。** 后台建索引，文件变了只重读那个文件；进 `perf-budget.tsv`；大仓库模式默认关。

## 三层，从外到里

| 层 | 是什么 | 怎么认 | 准不准 |
| --- | --- | --- | --- |
| 接口 | 方法 + 路径，如 `GET /api/orders/:id` | 后端的路由声明 ↔ 前端的请求调用，路径归一后配对 | 字面量路径：确定；模板 / 拼接：可能 |
| 功能 | 前端页面，如「订单详情页」 | 从调用请求的文件沿 `import` 往上找，找到路由表里的页面 | import 是写死的，确定 |
| 下游 | 服务端 handler 往下的函数、任务、表 | 在 handler 函数体里找调用，跟到项目里定义的函数，最多 3 层；终点按写法认 | 函数名配对：可能；ORM / SQL / 队列写法：确定 |

### 接口：两头怎么认

**后端的路由声明**（第一期覆盖这些，其余按真实项目再加）：

- Node：Express / Koa / Fastify 的 `app.get('/x', h)`、`router.post(...)`；NestJS 的 `@Controller('orders')` + `@Get(':id')`；Next.js 的 `app/api/**/route.ts`、`pages/api/**`（文件路径就是路由）。
- Python：FastAPI / Flask 的 `@app.get("/x")`、`@bp.route(...)`；Django 的 `urls.py` 里 `path("orders/<int:id>/", view)`。
- Java / Kotlin：Spring 的 `@RequestMapping` + `@GetMapping("/{id}")`。
- Go：`net/http` 的 `HandleFunc`、gin / echo / chi 的 `r.GET("/x", h)`。
- 有 `openapi.yaml` / `swagger.json` 时以它为准：接口列表从这里来，路由声明只用来找 handler。

**前端的请求调用**：`fetch`、`axios.get/post`、`ky`、`$fetch`、`useSWR`、`useQuery` 里的 URL；项目自己包了一层（`api.get('/orders')`、`request({ url })`）时，认出这个包装函数一次，之后调它的地方都算。OpenAPI 生成的客户端（`ordersApi.getOrder()`）按生成的函数名配。

**路径归一**：`/api/orders/:id`、`/api/orders/{id}`、`/api/orders/<int:id>`、`` `/api/orders/${id}` ``、`'/api/orders/' + id` 都归成 `/api/orders/*`。前端常有 baseURL 前缀（`/api`、`VITE_API_BASE`），按后缀配对，配上了标「可能」。

### 下游：认哪些终点

- **数据库表**：Prisma `prisma.order.findMany`、TypeORM / Sequelize / Django / SQLAlchemy / ActiveRecord 的模型名 → 表名（看模型上的 `@Entity('orders')`、`__tablename__`、`db_table`，没有就按框架默认规则推）；SQL 字符串里的 `FROM / INTO / UPDATE / JOIN 表名`；读还是写分开标。
- **后台任务**：BullMQ / Bee `queue.add('send-receipt')`、Celery `task.delay()` / `@shared_task`、Sidekiq `perform_async`、`asynq`；定时任务（cron 配置、`@Scheduled`）作为另一种上游，也能指到同一张表。
- **对外**：发出去的 HTTP 请求（第三方服务）、消息（`publish('order.paid')`）。消息和任务一样，能连到消费它的那一头。

## 放在哪里

### 1. 改动卡片上一行（主入口）

逐个验收的卡片头部已经有风险说明（`ReviewRisk`），在下面加一行，只在这处改动碰到了接口或它的下游时出现：

> 影响：3 个页面调这个接口（订单详情页、订单列表、退款弹窗）· 写 `orders` 表 · 发任务 `send-receipt`

- 这一轮 AI 同时改了调用方，标「本轮也改了 2 处调用」，点开直接看那两处改动。
- 改了接口但前端调用没跟着改（参数名、返回字段对不上），这是最值得拦的情况。第一期只说「调用方这轮没改」，不判断兼容性；第二期再比字段。
- 点这一行 → 打开调用关系页，以这个接口为中心。

### 2. 调用关系页

和「全部改动」「待办」一样占编辑区的位置。以一个接口（或一个函数）为中心，三栏：

| 往上：谁在用 | 中间：它本身 | 往下：它用了谁 |
| --- | --- | --- |
| 按页面分组的调用点，每条是 `文件:行`，可展开看那一行 | 方法 + 路径、handler 所在位置、这轮改了什么 | handler → 函数 → 表 / 任务 / 对外，缩进的树 |

- 每一行都能点，打开到那一行；这一轮改过的行标出来。
- 不做力导向的关系网：节点一多就看不清，也排不了顺序。三栏的树能用键盘走：←→ 换栏，↑↓ 选，⏎ 打开，⌫ 回到上一个中心。
- 点任何一个函数、表、页面 = 以它为中心重新展开，像浏览器一样能后退。以表为中心时就是「哪些接口、哪些任务会写 `orders`」。
- 顶部写这张图有多准：「12 条确定，3 条可能；没找到的不代表没有」。

### 3. 接口目录

⌘K 输入 `/` 前缀（或「接口」）列出项目所有接口：`GET /api/orders/:id · 3 个页面 · 读 orders`。没有前端调用的接口、前端调了但后端没有的路径单独一组，这两种常是 AI 改漏的地方。

### 4. 编辑器里

光标在函数名或路由上，按 ⌥⌘H（暂定）打开调用关系页。不做行内的「3 references」提示，不做悬停卡片。

## 前端和后端不在一个仓库

很常见。项目设置里加「关联项目」：选项目轨里的另一个项目（可以多个），两边的接口一起配对。存在 `ProjectPreferences` 里（新字段，`decodeIfPresent` 给空），只记对方的路径，不复制数据。关联的项目索引在后台读，关系图里跨项目的行带项目名，点了先切过去再打开。

## 实现

- 新的 `Sources/FolmiCore/CallMap/`：不依赖界面。文件列表用 `git ls-files`（自然跳过 `node_modules` 和忽略的文件）；每个文件按扩展名交给一个识别器，产出「声明」（路由、函数、模型、任务）和「引用」（请求、调用、查询、入队）；全部放进内存里的索引，按文件内容哈希缓存。
- 识别器先用正则加一点括号配对（找函数体范围），不引 tree-sitter：`direction.md` 里 tree-sitter 暂不做（+8 MB）。哪一种语言正则撑不住了，再为它单独接 tree-sitter，那时候它也能顺带给高亮用。
- 下游跟函数：只跟到项目里定义过的同名函数，最多 3 层，同名多处时标「可能」并列出来。
- 后台、增量：和 `MarkdownIndex` 一个思路，`RepositoryWatcher` 报了哪些文件变了就只重读哪些。首次建索引在打开项目后空闲时做；一万个文件以上的仓库要用户在设置里打开。
- 测试：每个识别器一组小样例（真实框架的写法），`DemoRepository` 加一个前后端小项目，测改动卡片那一行和关系页读回屏幕的文字。

## 认不出来的时候

- 关系页底部一个「问 AI」：把中心节点和已经认出来的关系发给 Claude Code / Codex（走现有的 ⌘L），让它补上漏的。它的回答留在它的对话里，不写回索引（不在 Git 之外记状态）。
- 认错了：每条「可能」的关系可以右键「不是这个」，按内容算 key 存进项目设置，下次不再显示。这是唯一记下来的东西。

## 分几步做

1. **接口配对**：后端路由 + 前端请求两头认出来，接口目录，改动卡片上「N 处调用这个接口」那一行。单仓库。先挑你项目用的框架做。
2. **页面和下游**：沿 import 找到页面；handler 往下到表、任务、对外；调用关系页三栏。
3. **关联项目**：前后端分仓库。
4. **对得上吗**：接口这轮改了字段，比对调用方用到的字段，对不上标出来；GraphQL（operation ↔ resolver）、gRPC（`.proto` 就是契约，最好做）。

每一步都能单独发，第 1 步就能回答「前端哪些地方用了这个接口」。

## 不做

跳到定义、查找所有引用的 IDE 版本、重命名重构、行内引用计数、调用关系网的大图、运行时追踪（埋点、APM）、连数据库读表结构。
