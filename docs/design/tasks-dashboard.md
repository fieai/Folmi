状态：**设计，待确认。** 样式稿见 [tasks-dashboard-mockup.html](tasks-dashboard-mockup.html)。

## 2026-10-26 调整：以随手记为主

做完第一步后重新想了范围：项目里所有 Markdown 的 `- [ ]` 大多不是「我的待办」（AI 写计划时留的步骤、文档里的清单），全列出来没有重点。改成：

- **默认只看随手记**：各项目 `ideas/` 里的待办，那是自己按快捷键记下的，每条都是自己的事。
- **范围默认所有项目**：随手记分散在各项目的 `ideas/`，但待办是一份清单。`ideas/` 文件少，每个项目读一遍很便宜。linked worktree 跳过，免得重复。
- **项目文档的待办留一个不显眼的入口**：页头一个小菜单切「这个项目的文档」，用现成的 `MarkdownIndex`，不为它多读文件。
- **完成时间写在行里**：勾了「只留在本机」的随手记 Git 看不到，流转没法从 Git 算；所以勾选随手记里的待办时总是写上 `✅ 日期`。项目文档仍然跟着文件走。
- **「AI 留下的」降级**：AI 很少写随手记。下面第 3 步的 Git 流转、AI 来源先不做，流转改用 `✅` / `📅` 日期统计。
- **不从 Folmi 交给 AI**：交代 AI 在 Claude App / Claude Code / Codex 里做，Folmi 只管记录和验收。面板往这两头发展，不加「发给 AI」的按钮。
- **主入口不变**：主窗口切换栏里的「待办」。点别的项目的待办 = 切到那个项目再打开到那一行。

### 已经做了的（未提交）

- 待办页：四个数字是没做完的、今天和过期的、这周到期的、这周做完的（按 `✅` 日期算，点开能改回没做完）。
- 右边月历（窗口宽于约 680pt 时显示，页头按钮可收起）：下划线是那天记过随手记（日期取文件名，不是 IdeaStore 命名的取创建时间），主题色点要做、红点过期、绿点做完；点一天列出那天的随手记（点开是阅读视图）和待办；把待办拖到某天改截止日期。
- 阅读视图：`[/]` 半满、`[-]` 划掉，日期显示成小标签；点 `[/]` 是完成，点 `[-]` 是改回没做完。

下文是最初的设计，和上面冲突的以上面为准。

## 现状

- 待办就是项目里 Markdown 的 `- [ ]` / `- [x]`，`MarkdownIndex` 在后台建索引。
- 入口：⌘⇧T「全项目待办」弹窗（按文件分组，能勾选、跳到那一行）、⌘K 里 `[` 前缀、文件树的进度环、随手记写进 `ideas/`。
- 缺的：
  - 看不到总量和变化，不知道是越来越多还是在减少；
  - 没有日期，排不出「今天做什么」「哪些过期了」；
  - 不知道一条待办从哪来（我写的、AI 写的）、什么时候做完的。

## 先对一遍原则

- **不在 Git 之外另记状态。** 日期写在待办那一行里（就是 Markdown 文本）；新加、完成的时间和是谁动的，从 Git 历史里算。Folmi 不存待办数据库，Markdown 文件就是全部。
- **和主循环的关系。** Claude / Codex 常在计划文档、TODO.md 里写 `- [ ]`，做完自己勾掉。Folmi 的面板要回答的是「AI 给我留了哪些事、它说做完的是哪些」，这是和 Obsidian dashboard 不一样的地方：Obsidian 管个人知识库，Folmi 看 AI 干了什么。
- **不做成另一个 App。** 不做提醒通知、重复任务、优先级、标签体系，不接系统日历和日程。

## 写法

照 Obsidian Tasks 的写法，从 Obsidian 来的笔记直接能用，AI 也认识：

| 写法 | 意思 |
| --- | --- |
| `📅 2026-10-30` | 截止日期 |
| `⏳ 2026-10-28` | 打算哪天做 |
| `✅ 2026-10-26` | 完成日期 |
| `- [/]` | 进行中 |
| `- [-]` | 不做了 |

- 现在的解析只认 `[ ]` 和 `[x]`，要加 `[/]`、`[-]` 和三种日期。日期从标题里拿掉，单独显示成胶囊。
- 插入日期：`/` 菜单加「截止日期」「哪天做」，输入 `📅` 时弹日期选择；面板里把待办拖到日历上某一天 = 改那一行的 `📅`。都走编辑器缓冲区，能 ⌘Z。
- 勾选时补不补 `✅ 日期`：跟着文件走，文件里已经有 `✅` 写法才补，否则不往 AI 写的文档里塞东西（完成时间从 Git 算，见下）。

## 流转：从 Git 算

一条待办的经过：**新加 →（进行中）→ 完成 / 不做了 / 删掉**。

- 来源：后台读 `git log -p --since=90.days -- '*.md'`，找待办行的增减对；去掉复选框和日期之后的「路径 + 文本」作 key，把「删了 `[ ] X`、加了 `[x] X`」配成一次完成。没提交的从工作区差异算，记在今天。
- 谁动的：提交作者，再加上 Claude Code 钩子记下的轮次（已知某一轮改了哪些行）→ 标「AI 加的」「AI 勾掉的」。
- 增量：按提交哈希缓存，新提交才读，和 `MarkdownIndex` 只重读变过的文件一个思路。进 `perf-budget.tsv`；大仓库模式下只看最近 30 天，或者关掉。
- 「AI 勾掉的」值得在验收里也露出来：一处改动里有 `[ ]→[x]`，改动卡片上写「勾掉了 1 条待办」，验收时知道它声称做完了什么。

## 入口

主区域顶部的切换（差异 / 编辑 / 全部改动 / 历史，`FolmiContent`）加第五个「待办」，和「全部改动」一样占编辑区的位置。原来的「全项目待办」弹窗去掉，不留两处一样的东西。

- ⌘⇧T：切到「待办」，再按一次回到之前的视图。
- ⌘K 输入「待办」、菜单「显示 → 待办」。
- 左边仍然是项目轨，不另加图标栏。

## 数据放在哪

| 东西 | 放在哪 |
| --- | --- |
| 待办本身 | 项目里的 Markdown 文件 |
| 截止 / 哪天做 / 完成日期 | 同一行文字里的 `📅` `⏳` `✅` |
| 汇总的列表 | 只在内存里，`MarkdownIndex` 后台读，文件变了只重读那个文件 |
| 新加、做完的时间，谁动的 | `git log` 现算；没提交的从工作区差异算 |
| 流转的缓存 | App 数据目录（和 `daily-stats.json` 一起），只是缓存，删了重算 |
| 设置（默认范围、补不补 `✅`） | 项目设置 `ProjectPreferences` |

不是 Git 仓库的文件夹：有待办和日期，没有流转和「谁动的」。

## 这个项目 / 所有项目

- 默认「这个项目」：项目轨上选中的那个。
- 页面顶部切到「所有项目」：项目轨里所有项目一起看，数字和日历合起来算，列表每行带项目名，可以按项目分组；点别的项目的待办 = 先切过去，再打开到那一行。
- 现在只有当前项目有索引，「所有项目」要在后台给每个项目各读一份（像项目总览读各项目的 `git status`），有上限；大仓库模式的项目不算流转。
- 同一个仓库的 worktree 待办基本一样，只算主工作区。

## 页面

宽窗口分左右两栏：

**左边：看全局**

1. **四个数字**（不做十几个卡片）：没做完的（比上周 ±）、今天和过期的、这周做完的（来自 Git）、AI 留下的（AI 加的、还没做完）。点一个 = 右边列表按它筛选。
2. **月历**：格子里列当天到期的待办（最多 3 条，再多写「还有 n 条」），格子底部一排小点表示当天做完几条。点一天 → 右边只看这天；拖待办到一天 = 改截止日期。今天加框，过期的标红。可切月 / 周。
3. **流转**：近 30 天每天「新加 / 做完」的柱子，叠一条「没做完的总数」折线，一眼看出在消化还是在堆积。下面是「最近动静」：「Claude 在 plan.md 加了 4 条（第 3 轮）」「你勾掉了『补测试』」……点开跳到对应轮次或提交。

**右边：做事的列表**

- 分组：过期 / 今天 / 这周 / 以后 / 没日期；可切成按文件分组。
- 每行：复选框、标题、文件名、日期胶囊、AI 来源标记。
- 键盘：↑↓ 选，空格勾选，⏎ 打开到那一行，D 设日期，⌘Z 撤销。
- 筛选框；范围：这个项目 / 所有项目。

窄窗口：只剩列表，数字收成一行，日历和流转折叠起来。

## 和现有功能接上

- 收工卡片加一行「今天做完 3 条待办」。
- 随手记 `ideas/` 里的 `- [ ]` 自然进来，不用另外处理。
- ⌘K 的 `[` 搜索同样显示日期。

## 分几步做

1. 弹窗换成页面：数字、分组列表、日期和 `[/]` `[-]` 解析、`/` 菜单插日期、列表里设日期。只读当前文件，不碰 Git 历史，所以数字先用不需要历史的四个：没做完的、今天和过期的、这周到期的、进行中的；「这周做完的」「AI 留下的」等第 3 步。
2. 日历：月 / 周，拖动改日期。
3. Git 流转：后台扫描、流转图、最近动静、AI 来源、验收卡片上的「勾掉了 n 条待办」。
4. 所有项目一起看、收工卡片。

每一步都能单独发。

## 不做

提醒通知、重复任务、优先级、标签体系、接系统日历、看板拖拽列（状态只有四种，看板列就是状态，列表分组已经够）。
