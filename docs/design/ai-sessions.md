# 选中就能问 AI，Codex 会话管理

日期：2026-10-28  
状态：交互已定（2026-10-28）；第 1、2、3 步已实施，第 3 步的「回到会话」和第 2 步的顶部胶囊提醒还没做。实验只接 Codex（`@agentclientprotocol/codex-acp`），代码保留 `AgentKind`，以后 Claude 照着接。

## 要解决什么

1. 看代码、看改动、读文档时，看不懂或想改一处，要先复制、切到终端、再粘贴说明在哪。应该**选中就能问、选中就能交给 Codex**。
2. 现在 AI 标签只有一个会话。想同时让 Codex 做两件事，或者回到昨天在 Codex 里聊的那个会话，都做不到。
3. 在 Codex CLI、Codex App、VS Code 里开的会话，Folmi 看不到。验收时看不懂某一轮改动，没法回到改出它的那个会话去问。

## 和现在的差别

| | 现在 | 这次 |
| --- | --- | --- |
| ⌘L 问 AI | 上下文是**整个文件**或整个改动，不管选区 | 有选区就用选区，没有才退回整个文件 |
| 交给 agent | 只能从 ⌘L 卡片点「交给 agent」 | 选区浮条、右键、⌘J 直接交给 Codex |
| 会话 | 每个项目一个，重启后只读 | 多个会话，标签切换；可以接回旧会话 |
| Codex 自己的会话 | 看不到 | 会话列表里按「在 Folmi 开的 / 在 Codex 里开的」列出，能打开、接着聊 |
| 窗口 | 只在终端卡片的 AI 标签里 | 会话可以拆栏并排，或者弹出成独立窗口 |

不变的：Folmi 不自己做 agent，写代码的是 Codex；Codex 改的东西照常进改动列表，一处一处验收；不给 Codex 收下、提交、推送的权限；不做常驻聊天侧栏。

## 一、选中就能唤起

### 选区浮条

在**代码编辑器、差异（选中几行）、Markdown 阅读视图、终端**里用鼠标选中文字，松开后在选区右上角出现一条小浮条：

```
        ┌──────────────────────────────────────────┐
        │ 问 ⌘L   交给 Codex ⌘J   说人话  解释  ⋯ │
        └──────────────────────────────────────────┘
  12 │ func refresh() async {
  13 │     guard !isBusy else { return }     ← 选中的几行
  14 │     ...
```

- **问 ⌘L**：就地卡片，一次性回答，用「解释改动 / 问 AI」用途配的模型（现有的 `AIAssistCard`）。回答完卡片上有「交给 Codex」，把问题和选区一起带进会话。
- **交给 Codex ⌘J**：选区变成一个附件，放进当前会话的输入框（**不自动发送**），光标落在输入框里，用户补一句「这里改成…」再回车。
- **说人话 / 解释 / 翻译**：现有的一次性操作，按场景显示：差异里显示「解释这处改动」，Markdown 里显示「说人话」「翻译」，终端里显示「说人话」。
- `⋯`：「交给新会话」「交给…（选一个会话）」。

浮条的规则，避免打扰：

- 只在鼠标选中后出现；用键盘 ⇧ 方向键选中时不出现（只用快捷键）。
- 选中不到 3 个字符时不出现；开始打字、按 Esc、滚动、点别处时消失。
- 设置里可以关掉浮条，快捷键照样能用。

### 快捷键

| 键 | 作用 | 备注 |
| --- | --- | --- |
| ⌘L | 问（有选区用选区，没有用当前文件或改动） | 现有，改成先看选区 |
| ⌘J | 交给 Codex（选区作为附件进当前会话） | 新增。⌘I 在 Markdown 里是斜体，所以不用它 |
| ⌥⌘L | 发送选中的行到终端 | 现有，不变 |
| ⌘⇧J | 打开 AI（会话区），没开就新建一个会话 | 新增 |

### 附件长什么样

输入框上方一排小标签，每个可以点 × 去掉，点一下预览内容：

```
 [ LoginView.swift:12–30 ] [ 差异 · Auth.swift 第 2 处 ] [ 评论 #3 ]
 ┌──────────────────────────────────────────────────────────────┐
 │ 这两处为什么不一样？统一成 Auth 里的写法                       │
 └──────────────────────────────────────────────────────────────┘
                                         Codex · gpt-5.x   发送 ⏎
```

发给 Codex 时，每个附件用 ACP 的 `resource`（带 `file://…#L12-30` 的 uri 和文字内容）；适配器不支持嵌入上下文（`promptCapabilities.embeddedContext` 为 false）时，退回成文字：「文件 LoginView.swift 第 12–30 行：……」。

可以变成附件的来源：编辑器选区、差异里选中的行或一整处、全部改动里的某一轮、审阅评论、终端选区、Markdown 阅读视图的选区（映射回源码行号）。

### 其他入口

- **⌘K**：没匹配到命令时最后一行「问 Codex：…」（现有）。再加「新建 Codex 会话」「打开会话列表」。
- **改动列表、差异的右键菜单**：「问 Codex 为什么这么改」。
- **按轮次看**：Codex 改出来的一轮，胶囊和轮次标题上有「回到会话」，打开改出这一轮的那个会话，并把这一轮的改动作为附件放好。验收时看不懂就直接问写它的人，这是 Folmi 和普通聊天框最不一样的地方。
- **审阅评论**：「交给 Codex」（评论作为附件），和现在的 MCP 读评论并存。

## 二、会话和窗口

### 会话在哪

会话区就是终端卡片现在的 **AI 标签**，升级成一排会话标签，和终端标签同一种心智：

```
┌ 终端卡片 ───────────────────────────────────────────────────────────┐
│ [≡] [● 修登录超时 ×] [◐ 补测试 ×] [ + ]   │  zsh   zsh      [⤢] [⧉] │
├────────────────────────────────────────────────────────────────────┤
│ 你：这里改成和 Auth 一样的写法  [LoginView.swift:12–30]              │
│ Codex：好，我先看一下 Auth.swift……                                  │
│   ✎ 改了 LoginView.swift  +8 −3            看改动                   │
│   ▸ 运行 swift build                       已完成                   │
│ ┌ Codex 想运行：git stash ─────────────────────────────────────┐   │
│ │ 允许一次   总是允许   拒绝                                     │   │
│ └──────────────────────────────────────────────────────────────┘   │
│ 这一轮改了 3 个文件 → 去验收                                        │
├────────────────────────────────────────────────────────────────────┤
│ [附件…]  输入…                                          发送 ⏎      │
└────────────────────────────────────────────────────────────────────┘
```

- **[≡] 会话列表**：见下节。
- **会话标签**：标题来自 Codex 给的会话名（ACP 的 `session_info_update`），没有时用第一句话的前 12 个字。标签前的圆点表示状态：
  - 空心：空闲
  - ◐ 转圈：正在工作
  - 橙色 ●：**等你允许**（后台的会话也要能一眼看到）
  - 红色：出错
- **[ + ]**：新建会话。按住或右键：「在新工作树里新建」。
- **[⧉]**：把当前会话弹出成独立窗口。**[⤢]**：卡片最大化（现有 ⇧⌘↩）。
- 关闭标签（×、⌘W）只是不显示，会话还在列表里；正在工作的会话关标签前要确认（「Codex 还在改，关掉标签它会继续改完」，不打断）。

### 会话列表

点 [≡] 或 ⌘K「打开会话列表」，在会话区左侧滑出一列（可以固定住），列出**这个项目**的全部 Codex 会话：

```
┌ 会话 ─────────────── [搜索] ┐
│ 打开着                        │
│  ● 修登录超时      刚刚       │
│  ◐ 补测试          2 分钟前   │
│ 在 Folmi 开的                 │
│    重构设置页      昨天  3 轮 │
│ 在 Codex 里开的               │
│    CLI  调查崩溃日志  10:20   │
│    App  写官网文案    周一    │
│    VS Code  改构建脚本  10/20 │
│                               │
│ [ 新建会话 ]                  │
└───────────────────────────────┘
```

- 数据来自 codex-acp 的 `session/list`（按项目目录 `cwd` 过滤），它本身就列 CLI、Codex App、VS Code、`codex exec` 开的会话。不在 Folmi 里另存一份列表：Folmi 自己开的会话也是 Codex 的会话，同一处来源，避免两套记录对不上（原则 1 的延伸）。
- 「N 轮」：这个会话在 Folmi 里留下了几轮改动（按 AI 批次里记的会话 id 统计），点进去可以按轮次看。
- 用工作树开的会话，分组下面标出工作树名字；切到别的工作树时列表跟着变。
- 右键：打开、在新窗口打开、复制会话 id、在 Codex 里打开（`codex resume <id>` 放进终端，不自动回车）。
- **不提供删除**：会话是 Codex 的数据，删除留给 Codex 自己。

### 打开一个在 Codex 里开的会话

- 点开后用 `session/load` 回放历史，先**只读**显示，输入框位置换成一条提示：

  > 这个会话是在 Codex CLI 里开的。如果那边还开着，两边同时发消息会乱。  [ 在这里接着聊 ]

- 点「在这里接着聊」后才真正接管，之后和 Folmi 里开的会话一样。
- 回放出来的历史里，文件修改那一行如果对应的改动还在工作区，照样显示「看改动」；已经提交或丢掉的，显示「已不在工作区」。

### 窗口管理

三种摆法，用户自己选：

1. **标签**（默认）：会话区里一个一个切换。
2. **并排**：沿用 [split-panes.md](split-panes.md) 的「栏」：会话标签可以拖到终端卡片的另一栏，最多 3 栏。原来「AI 标签固定在最左一栏」这条改成：会话标签可以放在任意一栏，终端标签和会话标签可以同栏。
3. **独立窗口**：[⧉] 或右键「在新窗口打开」。适合放到第二块屏幕上一边让 Codex 干活、一边在主窗口验收。
   - 独立窗口和标签是**同一个会话对象**，不是复制：两边内容同步，在任意一边发消息都行。
   - 窗口标题：「Codex · 修登录超时 — 项目名」。关掉窗口，会话回到会话区的标签里。
   - 窗口里点「看改动」时，主窗口跳到对应改动并激活主窗口。
   - 重启 App 后，上次弹出来的窗口按原位置恢复（只读回放，下一条消息再接上）。

### 后台会话怎么提醒

- 不在眼前的会话（标签没选中、窗口在后面）**等你允许**或**做完一轮**时：
  - 顶部胶囊显示「Codex · 补测试 等你允许」，点一下跳过去；
  - App 不在前台时发系统通知（沿用 `AINotifications`，同样不显示 Dock 角标）。
- 权限请求在会话里就地处理，也可以直接在胶囊的小弹层里点「允许一次 / 拒绝」，不用切过去。

### 同时开几个会话

- 同一种 agent 只起**一个适配器进程**，多个会话共用（ACP 一个连接本来就能开多个会话），不是一个会话一个 Node 进程。
- 两个会话**同时在同一个工作区里改**时，改动会混在一起。第二个会话开始工作时提示一次：

  > 「修登录超时」也在改这个工作区，两边的改动会混在一起，按轮次还分得开，但可能互相覆盖。  [ 知道了 ] [ 以后在新工作树里开 ]

  不禁止，因为一个查资料、一个改代码很常见。

## 三、和验收的衔接

会话区不是终点，最后都回到主循环：

- 每一轮结束，会话里显示「这一轮改了 N 个文件 → 去验收」，点了进全部改动，只看这一轮。
- 文件修改那一行的「看改动」跳到这个文件的差异，定位到改的那一处。
- 按轮次看的「回到会话」（上文）是反方向的入口。两边打通后：**会话 → 改动 → 看不懂 → 回到会话问**，不用复制粘贴。

## 分步做

| 步 | 内容 | 规模 |
| --- | --- | --- |
| 1 | 选区：⌘L 改成先看选区；⌘J 和附件标签；选区浮条（编辑器、差异先做，终端、阅读视图后补） | 中 |
| 2 | 多会话：会话标签、新建、状态圆点、一个适配器进程开多个会话、后台提醒 | 中 |
| 3 | 会话列表：`session/list`、只读回放、「在这里接着聊」、按轮次看的「回到会话」 | 中 |
| 4 | 窗口：拆栏放会话标签、弹出独立窗口、重启恢复 | 中 |
| 5 | 在新工作树里开会话 | 小 |

每步单独能用，前一步不依赖后一步，只有第 3 步「回到会话」要先确认下面第 1 条。

## 实施前要确认的事

1. **钩子记的会话 id 是不是 ACP 的会话 id。** AI 批次（`AIEvents` 的 `session`）记的是 Codex 钩子给的 id；codex-acp 的会话 id 是 Codex 的 thread id。一样的话「回到会话」直接能用；不一样就要在会话开始时记一张对照表。
2. **同一个会话两边同时开会怎样。** CLI 里开着、Folmi 里又 `session/load` 同一个会话并发消息，Codex 会不会把两边的历史写乱。实测之后决定「在这里接着聊」要不要做得更严（比如检测到那边在写就不让接）。
3. **`session/list` 的速度。** 会话多的项目（几百个）第一次打开列表要多久；慢的话先显示缓存，后台刷新。

## 已定的事（2026-10-28）

1. 「交给 Codex」放进输入框，不自动发送。
2. 第一版不做独立窗口，第 4 步只做拆栏。
3. 随手记、待办也能交给 Codex：待办页和随手记里的一条，右键或 ⌘J 作为附件进会话。[direction.md](../direction.md) 已跟着改。
4. 别处开的会话只读，不做「在这里接着聊」（2026-10-28 改）：codex-acp 的 `session/load` 在 Codex App、CLI 或编辑器开着这个会话时直接报错，两个客户端写同一个会话也会乱。改成直接读 Codex 的会话记录（`~/.codex/sessions/…/rollout-…-<id>.jsonl`，旧的是 `.zst`，要 zstd 才能读），要接着聊就把 `codex resume <id>` 放进终端。下面「打开一个在 Codex 里开的会话」一节以这条为准。
